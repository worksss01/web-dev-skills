# Web Debug 1.8.3 — modern design by default

The 1.8.2 guidance requested expanded-state review but still allowed an agent to accept stock native options by judging them suitable. Its instruction was also behind reference links. A later real-use report exposed the same closed-trigger-only styling gap in a catalog sorter.

This patch places a modern-by-default requirement directly in both host entry points and the website-design route. Website creation and design/redesign must use a contemporary visual approach unless the user explicitly requests a classic, retro, legacy or platform-native appearance. The requirement covers the complete in-scope page and interactive states, including dropdowns, menus, pickers and dialogs; it applies even when a short brief leaves style unspecified.

The requirement concerns rendered output, not a ban on native HTML semantics, serif type or a mandate to install a particular library. Single-choice controls need designed expanded options, verified visually and through the resulting task state. A stock popup with only a styled trigger is unfinished work. A platform/accessibility or verification limit must be reported as unresolved, not used to silently ship a legacy-looking fallback as complete.

Focused bug fixes preserve unrelated existing UI. The evaluator gains an unqualified catalog brief to test the default and a deliberately classic brief to test the user-request exception. These cases are available for future independent runs; no new cross-model performance result is claimed.

This is an instruction correction, not a technical lock on the host AI or proof that every model will comply. The only executable helper change is VERSION. No dependency, telemetry, new access capability or automatic user-project edit is introduced. User-supplied project content is excluded from the release.

Signed patch updates follow the existing 1.8.x enrollment policy; Cowork account ZIP replacement remains manual. See [validation](VALIDATION-1.8.3.md).
