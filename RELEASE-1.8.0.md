# Web Debug 1.8.0 — design from short briefs

Website creation now has its own entry path: infer the brief, inspect relevant visual references, choose an original direction, resolve typography/assets/composition, and refine rendered work. Focused bug fixes retain their smaller diagnostic workflow and existing design system.

The compact pattern reference covers eight page/task archetypes and six visual directions, with dated observations from eight public examples. It describes transferable mechanisms and limitations rather than distributing copied prompts, images or templates. Reference pages cannot authorize installs, code uploads, credentials or other external actions.

Core and Cowork route to the same design guidance. The existing direct-CDP helpers and conservative design-audit limits are preserved; the only core executable change is the release version. No additional runtime dependency, cloud account, telemetry or resident service is introduced. Large research notes and demonstration assets are not installed with the skill.

Maintainer-only brief cases cover product design, operational work, Thai content, existing-brand preservation, motion fallback, offline references and hostile reference instructions. Functional results and visual judgments remain separate. This release does not claim independent cross-model superiority, an automatic beauty score or guaranteed aesthetic outcomes.

This is a minor release. Patch-only managed installations do not cross from 1.7.x automatically. A deliberate local migration can install the reviewed release while keeping patch-only policy for 1.8.x. Cowork account-uploaded ZIP replacement remains manual. See [validation](VALIDATION-1.8.0.md), [updates](docs/UPDATES.md) and the [maintainer workflow](docs/MAINTENANCE.md).
